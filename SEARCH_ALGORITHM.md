# Поиск исполнителей

Как собирается выдача машин для клиента. Сценарий — `USER_SCENARIOS.md`.

Календаря занятости нет. Система не считает, свободна ли машина по времени. Для срочного заказа единственный признак доступности — ручной флаг исполнителя «принимаю срочные заказы».

## 1) Сначала фильтр заказа

Клиент заполняет (экран фильтра / черновик / будущий заказ), затем ищет.

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `category_id` | да | тип транспорта из `machinery_categories` |
| `pricing_type` | да | тариф, разрешённый категории |
| `quantity` | да | часы / смены / сутки / месяцы / рейсы / км |
| `search_mode` | да | `urgent` или `planned` |
| `planned_start_at` | только для `planned` | дата и время начала, выбирается в календаре; **справочно** для исполнителя, на выдачу не влияет |
| `lat`, `lng` | да | точка работ (для расстояния) |
| `max_amount` | нет | потолок посчитанной цены |
| `radius_km` | нет | фильтр по дистанции |

У `urgent` даты нет. У `planned` только дата и время начала, без окончания. Длительность и занятость из тарифа и количества **не выводятся**.

Стоимость по карточке: `machinery_pricing_rules.base_rate` выбранного тарифа × `quantity`. Клиент сумму не вводит. Какие тарифы вообще доступны — задаёт тип транспорта (`TARIFF_TYPES.md`): у одних часы/смены/месяцы, у других километры и рейсы.

## 2) Кого показываем

Карточка выдачи — **единица транспорта**.

Единица попадает в выдачу, если одновременно:

- не удалена;
- категория совпадает;
- есть активный тариф нужного `pricing_type`;
- если `search_mode = urgent` — у владельца `accepts_urgent_orders = true`; для `planned` флаг не проверяется;
- если `executor_subscription_enabled` — подписка `active` (пока флаг выключен, проверка не действует);
- если у категории `license_category` не пустой — у исполнителя лицензия на **эту категорию** в статусе `approved`;
- не своя машина;
- не исполнитель с `declined` / `auto_declined` / `expired` / `negotiation_rejected` / `terms_expired` по `exclude_for_order_id` (поиск в рамках существующего заказа);
- если задан `max_amount` — `base_rate × quantity ≤ max_amount`;
- если задан `radius_km` — дистанция ≤ радиуса.

Текущие заказы исполнителя (в переговорах, в работе, в споре) на выдачу **не влияют**. Один исполнитель может одновременно получить несколько запросов от разных клиентов; что с ними происходит при принятии — `ORDER_STATE_MACHINE.md`, раздел 6.1.

## 3) Сортировка и фильтры

Список: **по расстоянию** от точки работ до локации машины, по возрастанию (первый — ближайший).

При одинаковом расстоянии (округление до 0.1 км) — меньшая посчитанная цена.

Внутренний рейтинг в сортировке **не используется** и в UI не показывается.

Клиент сужает выдачу фильтрами (это параметры того же запроса, не отдельный ранжирующий ключ):

- расстояние (`radius_km`);
- потолок цены (`max_amount`).

Смена тарифа или количества — перезапрос: цена пересчитывается на сервере. Смена даты планового заказа выдачу не меняет.

## 4) Карта

Те же элементы, без своей сортировки. Точки с одинаковыми координатами — счётчик `+N`, по клику список машин точки.

## 5) Запрос после выбора

`POST /orders` (или отправка из черновика) с `machinery_unit_id`, копией фильтра и `computed_amount` на момент отправки. Дальше матчинг — один ожидающий кандидат на заказ, 5 минут, как в `ORDER_STATE_MACHINE.md`.
