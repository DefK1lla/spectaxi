# Правила сервиса SpexTaxi

Текст для пользователя (экраны, оферта) должен включать эти нормы. Блокировка — только админ.

## Сроки

- Исполнитель отвечает на новый запрос за **5 минут**, иначе запрос снимается и это считается отказом. Плановый заказ — тот же срок.
- Исполнитель подтверждает условия за **1 сутки** после принятия запроса, иначе заказ возвращается к поиску исполнителя.
- При безопасной сделке клиент оплачивает за **1 сутки** после «подтвердить условия», иначе заказ возвращается к поиску исполнителя.
- Исполнение подтверждают **обе** стороны. Если один подтвердил, второй молчит **1 сутки** — работа считается принятой (в пользу того, кто сдал работу). Открытый за это время спор отменяет автоприёмку.
- Срочный заказ без найденного исполнителя снимается через **24 часа** без действий клиента; плановый на `published` — при наступлении даты и времени начала. Клиенту предлагается создать заказ заново. Если плановый уже в `scheduled`, в эту дату он переходит в работу; неявка исполнителя — на усмотрение клиента (в т.ч. спор).
- Плановый заказ в статусе `scheduled` можно отменить с причиной до даты начала. После автоперехода в `in_progress` разногласия решаются через спор.
- Эти сроки должны быть написаны в правилах в приложении.

## Отмена и отказ

- Исполнитель на переговорах и оплате не отменяет заказ клиента, а отклоняет партнёра — заказ возвращается в поиск. На `scheduled` планового заказа отмена с причиной доступна обеим сторонам.
- Отказ и молчание на запрос равнозначны: исполнитель по этому заказу больше не предлагается.

## Запрещено (блокировка аккаунта)

Админ блокирует (`users.blocked_at`, причина) за:

- поддельные или чужие документы лицензии;
- систематический выход на заказ без лицензии / на чужой категории;
- угрозы, оскорбления, вымогательство в чате спора или после обмена контактами;
- мошенничество с оплатой и холдом (chargeback-схемы, «работал — денег нет» при доказанном объёме);
- создание нескольких аккаунтов для обхода бана или рейтинга;
- размещение техники, которой нет, или фото чужой техники как своей.

Заблокированный не виден в поиске, не создаёт и не принимает заказы. Все его **незавершённые** заказы (не `completed` / не уже `cancelled`) система переводит в `published`: открытые споры по ним закрываются системой, кандидаты/назначения снимаются по `ORDER_CONSISTENCY.md`, клиент снова ищет исполнителя. Если по заказу была оплаченная безопасная сделка и холд ещё `authorized` — деньги **возвращаются** клиенту. Если уже `captured` — автоматический возврат через провайдера нельзя (§5.5 FSM); заказ всё равно уходит в `published`, дальше ручной разбор. При отзыве лицензии (`revoke` / снятие `approved`) — то же, но только для заказов **этой категории**.

Лёгкие нарушения (разовый срыв с причиной из справочника) — внутренний рейтинг, не бан.

Если выплата по заказу уже ушла (`captured`), админ **не возвращает и не переводит деньги** (ни через провайдера, ни вручную «из кармана» платформы). Он может применить санкции к пользователям (рейтинг, блокировка), если нарушение **доказано** по материалам спора. Обещать клиенту возврат после выплаты в продукте нельзя. Компенсация / взыскание — **до юр. модели** не делаем (`PRODUCT_FOUNDATION.md` §17, `ORDER_STATE_MACHINE.md` §5.5).

При прямом расчёте (`direct_payment`) платформа денег не держала: исход спора — статус заказа и санкции при доказанной вине, без денежных операций платформы.

Chargeback банка после выплаты — ручной разбор админом (алерт), без автовозврата через сделку.

## Лицензии и верификация

Тип транспорта — строка таблицы `machinery_categories`: системный `code`, обязательный тип лицензии из справочника `license_types` (какая категория прав нужна для этого типа), текст для интерфейса. Типы транспорта и типы лицензий создаёт и правит админ.

Чтобы машины категории попали в поиск, админ должен **верифицировать** комплект документов исполнителя по этой категории (`approved`). Без `approved` в поиске нет.

Обязательные документы в комплекте (проверяет админ):

1. **Водительские права** нужного типа (`license_types` у категории).
2. **Любой документ**, подтверждающий право пользования техникой этой категории (собственность, аренда, доверенность и т.п. — формулировку не ограничиваем списком кодов).

Срока действия лицензии в системе **нет** (полей expiry / автопротухания нет). Повторная проверка — только если админ отклонил, отозвал `approved` или сменился тип лицензии у категории.

Смена типа лицензии у категории — лицензии исполнителей по ней перестают быть действительными, машины выпадают из поиска до новой подачи и `approved`.

## Споры

Разбор — в чате спора. Решение админа обязательно. На заказ может быть несколько споров (история претензий); одновременно открыт один. Апелляция — не больше одной **на каждый** спор; либо новая претензия отдельным спором (если ещё можно открыть). Обращения в поддержку не по заказу в MVP нет.

Открыть спор можно из `in_progress` или из `completed` в течение **2 суток** после завершения. После выплаты исполнителю спор всё ещё допустим в этом окне; деньги через провайдера платформа уже не двигает — см. выше. Пока спор открыт — заказ в `disputed`, автоприёмка и выплата по сделке не идут, пока админ не закроет.
