# Отменённые и повтор заказа

Утверждён вариант **B** для отменённых: строка в БД остаётся, в активных её нет, в архиве фильтр.

Отклонение партнёра заказ не отменяет: тот же `orders`, клиент продолжает поиск без новой анкеты — **только** пока заказ в `published` / `in_negotiation` / `assigned`. После начала работы поиск на этом заказе не продолжается.

На `published` полная отмена клиентом **без причины**.

## Кнопка «такой же заказ»

Создаётся **новый** заказ с копией полей старого (категория, режим поиска, адрес, координаты, плановые дата/длительность, описание, режим расчёта). Связь: `repeated_from_order_id`. Новый заказ в `published` без кандидата.

Доступно с:
- `cancelled` — любой способ отмены, включая автоотмену за неоплату;
- `completed` — только после **принятия** работы (кнопка клиента или автоприёмка через 1 сутки). Пока клиент ещё не ответил на сдачу — кнопки нет.

После закрытия спора/апелляции в `cancelled` или принятый `completed` — та же кнопка. Вернуть исходный заказ в `published` нельзя.

- Отменил **клиент** (кнопкой, до начала работы) — сразу диалог «искать снова?». Да → `POST /orders/{id}/repeat`.
- Отменил **исполнитель** — клиенту уведомление. По нажатию тот же вопрос.
- Автоотмена неоплаты — уведомление клиенту, можно repeat.

## Причина на заказе

При отмене с причиной (не `published`):

- `cancel_reason_code`
- `cancel_reason_text` (для `other`)
- `cancelled_by_user_id`
- `cancelled_by_role` (`client` | `executor` | `system`)

Автоотмена неоплаты: `cancelled_by_role = system`, кода из справочника клиента нет.

Исход `cancelled` после спора выставляет админ. На `disputed` кнопки отмены нет.

Отказ партнёра без отмены заказа — в `order_candidates` (`reject_reason_code` / `reject_reason_text`).
